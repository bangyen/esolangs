boolean: drop instantiate's unused complement argument

instantiate filled a `{Ci}` placeholder from a `set_comp` callable beside
each `{Xi}`, for a generator that wanted `1 - bit` embedded as a constant.
No generator wants it: bfpda's node marker is a constant that never depends
on the bit, and nocomment computes each complement at runtime from `{Xi}`
with its `s`-as-NOT-gate.  Checked rather than assumed -- no template at
n <= 3 emits a `{Ci}` -- so all nineteen call sites were passing a lambda
whose result was substituted into nothing.

Remove the parameter, the `SetComp` alias, and the nineteen dead lambdas.

The embed-once test counted `{Ci}` alongside `{Xi}`; it now asserts the
placeholder is absent.  With nothing left to fill it, a template that
emitted one would pass the literal text through to the interpreter rather
than fail, which is worth a guard.

No generated program changes: every example file is byte-identical.
